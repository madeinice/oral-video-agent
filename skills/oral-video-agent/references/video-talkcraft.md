# 与 video-talkcraft 协作制作动效

用户要求“动效剪辑用 video-talkcraft”时启用本流程。`video-talkcraft` 是独立安装的 Skill；本仓库不包含它的代码、动效卡、素材或运行环境。先确认 Agent 能读取它的 `SKILL.md`，再按需读取其 `references/taxonomy.md`、对应的 `references/cards/<slug>.md` 与人物镜头说明。找不到该 Skill 时说明缺口和安装来源，不声称已经使用。

## 使用前核对

- [video-talkcraft 的许可证](https://github.com/Vincentwei1021/video-talkcraft/blob/main/LICENSE)写明：非商业使用免费，商业使用工具包须先取得作者授权。用于销售、品牌或客户视频时，先核实相应授权；未取得授权时继续使用本 Skill 自带的 Remotion 动效，不运行或复制该工具包。不要把它的代码或卡片复制进本仓库并当作本仓库的 MIT 内容发布。
- 用户已确认的文案、镜头安排、人物出场区间、声线、语速、画幅、画质和风格优先于两个 Skill 的默认值。`video-talkcraft` 的横屏默认、全片配音或 Fish Audio 路线、人物常驻规则、运行环境升级步骤，不自动覆盖本项目设置。
- `oral-video-agent` 继续负责 RunningHub 配音与数字人、素材来源、词语锚点、`timeline.json`、工程交付和费用/断点记录。`video-talkcraft` 在这里负责镜头动效设计、挑选合适的配方和检查画面节奏；不要让两边各自生成一份音频、时间轴或整片工程。

## 交接和落地

1. **审核稿阶段**：按原有五列表把用户说的画面意图写成具体动效；若已可使用 `video-talkcraft`，在动效列附上拟用配方名称。此时用口播短语作为锚点，不编造精确秒数。用户仍只需审核画面，不必懂卡名、缓动和坐标。
2. **素材锁定后**：传给动效阶段的是定稿文案、最终完整配音、真实词级时间戳、仅需出镜区间的人物片段、已选 B-roll/图片、审核版分镜和画幅/色彩/字幕/音效要求。人物片段与对应配音核对时长和起点；全屏素材段只有人声，没有人物片段。
3. **选卡**：先根据语义查 `video-talkcraft/references/taxonomy.md`，再读少数匹配卡的说明。比如有先后依赖的流程可评估 `step-timeline-vertical`，人物缩位可评估 `host-shrink-to-chip`，人物身后大字可评估 `behind-text-title`。记录选用理由、触发短语、入场/停留/退场、遮脸风险及音效；不要为每句话机械加一张卡。
4. **建立镜头工作单**：在当前视频项目的 `work/motion-shotbook.md` 保存“口播片段 → 词语锚点/实测时间 → 人物/B-roll 图层 → 配方或自制动效 → 音效 → 所需素材 → 检查点”。这份工作单补充已审核的五列表，`timeline.json` 仍是生成阶段的时间真源；改时间要同步字幕、素材、音效和动画。
5. **落入现有 Remotion 工程**：优先依据选中配方的动作说明，在本 Skill 的分层工程中实现。若需复用 `video-talkcraft` 的 TSX/素材，逐项检查其依赖、许可证和署名要求，单独标明第三方部分；不要把其整套 runtime、模板或工作台覆盖到现有工程。保留可编辑文字、人物、B-roll、字幕和音效轨。
6. **预览与验收**：优先渲染动效密集的短段，核对词语触发、人物脸部安全区、色调统一、字幕可读和音效不盖人声。根据具体缺陷修改受影响镜头，之后再导出整片。

用户明确要求完全改用 `video-talkcraft` 的工程与渲染管线时，先展示工程格式、依赖、迁移范围和已有工程如何保留；按用户确认的方案执行，不把本页的“动效协作”误称为完整切换。
