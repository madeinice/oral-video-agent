# 常见问题

## 配音慢、声音假

速度由模型生成节奏、参考音频、停顿/标点和后续变速共同决定；数字人视频主要跟随音频。先检查 TTS 成品，不把音色问题当数字人模型问题。用清晰、自然、无音乐且音色稳定的样本；先用短语调参，再锁定整篇。约 5 字/秒并不意味着每句机械等速。

## 口型或动作不自然

确认喂给人物模型的就是最终音频；检查照片清晰度、脸部尺寸、姿势、背景及工作流输入类型。视频参考只有明确支持视频驱动的应用才能传入；不得把视频首帧当作“用了动态视频参考”。适量眨眼和头肩动作比强行夸张动作稳定。不能承诺单张照片完全复现本人习惯。

## Windows Remotion 原生程序报 0xC0000005 / 3221225477

先对安装的 ffprobe/ffmpeg 执行 `-version`，并核对依赖同版。若打开媒体前就失败，分别排查受限进程环境、损坏安装、运行库/系统兼容性；该退出码并不唯一指向权限或内存。

已有案例：官方包哈希一致、同一程序在普通用户进程正常，但在 Agent 受限执行环境崩溃。此情形使用宿主支持的普通执行审批再验证，不重复下载，不替换 DLL，不关闭全局防护。仅增加磁盘写权限并不等价于改变执行环境。

## Studio 网址打不开

本地网址需要本机服务持续运行。检查端口、启动日志、项目 tsconfig 和 node_modules，再检查 HTTP。使用 `studio.ps1 -Action Start` 后另一次请求确认页面能打开；浏览器编译还需检查 bundle/页面报错。不同项目不能仅因端口 200 就认作成功。

启动器记录本工程服务 PID 与启动时间，Stop 只停止该记录且身份一致的进程树。不得结束所有 node.exe 或用户浏览器。重启电脑后重新启动服务；MP4 与源工程文件仍在磁盘。

## 内存不足

先测当前可用物理内存和占用进程。历史“可用约 3.4 GB”不是机器总内存，也不是永久固定容量。优先关闭不再使用的视频编辑器、多余浏览器标签、旧 Studio/渲染；让用户保存工作后自行关闭应用。渲染并发设 1，限制 offthread 缓存，长素材可先裁切。云端显存不足改云端工作流配置，关闭本地应用无助于云端显存。

## 本地工程被重新编译覆盖

保留 `work/build-state.json`。编译器发现 Generated.tsx 或 meta.json 与上次生成哈希不同，会停止；先合并 Studio 修改，用户确认需要覆盖时才使用 `--overwrite-edits`。已有源工程应先做快照。不用成片 MP4 代替源图层。
